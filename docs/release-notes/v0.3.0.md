# v0.3.0 — MCP safety model + official MCP Registry manifest

## What changed

- **Honest MCP annotations**: every advertised tool carries `readOnlyHint`,
  `destructiveHint`, `idempotentHint`, `openWorldHint` (`src/mcp/safety.ts`);
  scanners and gateways can reason about the surface.
- **In-process rate limits**: per-tool sliding-window budgets stop runaway
  agent loops even when the client ignores annotations (destructive tools:
  5/min).
- **Recoverable deletions**: `remove_rule` / `remove_decision` archive the
  exact source bytes under `.syncytium/memory/trash/` before deleting;
  new `syncytium_list_trash` and `syncytium_restore` tools undo the operation
  (20 → 22 tools). Destructive tools are dry-run by default.
- **`server.json`** in official `registry.modelcontextprotocol.io` format,
  schema-validated and version-pinned by a unit test.
- **CI**: release job is idempotent (re-running never double-publishes),
  Dependabot noise grouped, checkout/setup-node bumped to v7, drift gate runs
  the local CLI instead of a stale global install.

## Verified gates

124/124 tests, `lint` clean, `diff` shows zero drift, npm package published
with provenance and verified via global install.

## Migration

No breaking changes. Destructive MCP calls that used to delete immediately
now require `dryRun: false` **and** `confirm: true`.
